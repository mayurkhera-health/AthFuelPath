# Auth v2.1 — Phase 4 (Remove Legacy Email-Only Session Issuance) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every remaining path where knowing a parent's or athlete's email is, by itself, sufficient to obtain an AthFuelPath session — replacing each one with the already-built, already-deployed secure mechanisms from Phases 2-3 (`POST /api/auth/email/request` + `/verify`, `GET /api/auth/session`).

**Architecture:** Two backend routes (`POST /api/auth/login`, `POST /api/parents/login`) are deleted outright — they mint a session from an email string match alone, with no proof of ownership. A third (`POST /api/auth/athlete-create-login/{id}`) is not deleted (it serves a distinct purpose — first-time athlete login creation, not returning-user login) but is hardened with a mandatory OTP-verification gate, closing the same class of gap for that flow. On mobile, three screens that called the retired paths are rewired: the main login screen becomes a two-step email→OTP flow; the onboarding success screen switches from a redundant email-based re-login to the token it already holds plus `GET /api/auth/session`; the athlete-claim screen gains an OTP-verification step before it can create a login.

**Tech Stack:** FastAPI + psycopg3 (backend). Expo Router + Zustand + Jest/ts-jest (mobile). No new dependencies, no schema migration — this phase only removes/rewires code, it does not add new OTP infrastructure (Phase 2's `otp_auth.py` already has everything needed).

**Spec:** `docs/superpowers/specs/2026-08-20-auth-onboarding-v2.1-design.md`, Part 4 "Phase 4" ("Delete/replace every mobile/backend call path where an email alone can mint or refresh an AthFuelPath session, including the currently identified login, silent-restore, athlete-claim, and success/revalidation call sites... After this phase: knowing an AthFuelPath user's email address alone must be insufficient to obtain a session token anywhere in the system"), plus the user's explicit Phase 4 investigation request and required outcomes.

**Worktrees:**
- Backend: `~/FuelUpYouth-auth-v2.1`, branch `feature/auth-v2.1` (needs to be brought back in sync with `main`, which has moved to `dedb5f9` after the Phase 3 merge/deploy — this worktree is currently behind).
- Mobile: `~/FuelUpYouth_Mobile/fuelup-mobile-auth-v2.1`, branch `feature/auth-v2.1` (needs to be brought back in sync with mobile `main`, now at `9bc8af1` — this worktree is currently behind).

**Explicitly out of scope for this phase** (per the user's instructions — do not build any of this here):
- Google, Apple, the Phase 5 common identity resolver
- Public signup redesign, athlete invitation codes (Phase 8's eventual full replacement for the claim flow)
- Refresh tokens, `jti`/session revocation
- Any auth UI beyond what's strictly necessary to stop calling the retired endpoints (no "remember me," no password manager integration, no social login buttons, no design-system changes)
- Unrelated authorization/business-logic cleanup

 * single-step, email-only /api/auth/login flow: knowing an email address is
 * no longer sufficient to obtain a session. Step 1 requests a 6-digit code
 * via the neutral, non-enumerating POST /api/auth/email/request; step 2
 * verifies it via POST /api/auth/email/verify, which only then issues a
 * real session.
 */
export default function LoginScreen() {
  const router = useRouter();
  const setSession = useAuthStore((s) => s.setSession);
  const setAthleteSession = useAuthStore((s) => s.setAthleteSession);

  const [step, setStep] = useState<"email" | "code">("email");
  const [email, setEmail] = useState("");
  const [code, setCode] = useState("");
  const [loading, setLoading] = useState(false);

  const handleRequestCode = async () => {
    if (!email.trim()) return;
    setLoading(true);
    try {
      await api.post<any>("/api/auth/email/request", { email: email.trim().toLowerCase() });
      setStep("code");
    } catch (e: any) {
      Alert.alert("Couldn't send code", e?.message || "Please try again.");
    } finally {
      setLoading(false);
    }

  const handleVerifyCode = async () => {
    if (!code.trim()) return;
    setLoading(true);
    try {
      const trimmedEmail = email.trim().toLowerCase();
      const data = await api.post<any>("/api/auth/email/verify", { email: trimmedEmail, code: code.trim() });

      if (data?.role === "athlete" && data?.athlete) {
        setAthleteSession(data.athlete, trimmedEmail, data.session_token);
        router.replace("/(app)/today");
      } else if (data?.role === "parent" && data?.parent) {
        setSession(data.parent, data.athletes ?? [], data.session_token);
        const { scheduleReady } = useAuthStore.getState();
        router.replace(scheduleReady ? "/(app)/today" : "/(app)/blueprint");
      } else if (data?.verified && data?.has_account === false) {
        Alert.alert(
          "No account found",
          "That email doesn't have an AthFuelPath account yet. Ask your parent to set one up first.",
