# Auth v2.1 — Phase 3 (Secure Session Restoration) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an already-authenticated parent or athlete reopen the mobile app and restore their session from the stored AthFuelPath bearer token alone — no OTP, no email-based revalidation call — while the token remains valid.

**Architecture:** One new backend endpoint, `GET /api/auth/session`, gated by the existing `require_session` dependency (401 on missing/malformed/expired token, zero email involvement) — it looks up the identity's current parent-or-athlete account and returns the same account-context shape the rest of the app already knows how to consume, minting no new token. On mobile, `store/authStore.ts`'s `hydrateFromStorage()` is relaxed to key its restoration gate on the stored session token instead of the stored email (the exact structural gap the original spec flagged: a valid token with no stored email currently fails to restore), and `app/_layout.tsx`'s `AuthGuard` launch-revalidation effect is rewired to call the new token-based endpoint instead of the old email-based `/api/auth/login`/`/api/parents/login` revalidation calls — everything downstream of a successful restore (query invalidation, push-token registration, scheduleReady check) stays exactly as it is today, just triggered off the new call's success instead of the old one's.

**Tech Stack:** FastAPI + psycopg3 (backend). Expo Router + Zustand + Jest/ts-jest (mobile). No new dependencies, no schema migration.

**Spec:** `docs/superpowers/specs/2026-08-20-auth-onboarding-v2.1-design.md`, Part 4 "Phase 3", plus the user's explicit Phase 3 requirements (token-only restoration, no email as auth proof, no new token minted, 401-only global logout preserved, 403 never globally clears session, unchanged TTL/format).

**Worktrees:**
- Backend: `~/FuelUpYouth-auth-v2.1`, branch `feature/auth-v2.1` (currently identical to `main` @ `00b4a50` — continuing on this same branch/worktree).
- Mobile: `~/FuelUpYouth_Mobile/fuelup-mobile-auth-v2.1`, branch `feature/auth-v2.1` (currently identical to mobile `main` @ `cb15de8`, unchanged since the Phase 0 mobile merge — continuing on this same branch/worktree).

**Explicitly out of scope for this phase** (per the user's instructions — do not build any of this here):

```python
@router.get("/session")
def get_session(identity=Depends(require_session)):
    """
    Phase 3 — restore an existing session from the bearer token alone. No
    email is accepted or consulted anywhere in this handler; require_session
    (401 on missing/malformed/expired) is the only gate. Mints no new token
    — the client already has one and keeps using it; this endpoint only
    re-confirms it's still good and returns fresh account context.
    """
    conn = get_conn()
    try:
        if identity.role == "parent":
            parent = conn.execute(
                "SELECT * FROM parents WHERE id = %s", (identity.parent_id,)
            ).fetchone()
            if not parent:
                # Token is well-formed and unexpired, but the account behind
                # it is gone (e.g. deleted) — treat as an invalid session,
                # not a permissions problem, so the client's existing
                # 401-clears-session handling applies.
                raise HTTPException(401, "Session no longer valid.")
            parent_d = dict(parent)
            athletes = [dict(a) for a in conn.execute(
                "SELECT * FROM athletes WHERE parent_id = %s", (parent_d["id"],)
            ).fetchall()]
            return {"role": "parent", "parent": parent_d, "athletes": athletes}

        athlete = conn.execute(
            "SELECT * FROM athletes WHERE id = %s", (identity.athlete_id,)
        ).fetchone()
        if not athlete:
            raise HTTPException(401, "Session no longer valid.")
        athlete_d = dict(athlete)
        al = conn.execute(
            "SELECT email FROM athlete_logins WHERE athlete_id = %s", (athlete_d["id"],)
        ).fetchone()
        return {
            "role": "athlete",
            "athlete": athlete_d,
            "email": dict(al)["email"] if al else None,
        }
    finally:
        conn.close()
```

(The athlete branch looks up `athlete_logins.email` because the `athletes` table itself has no email column — the mobile client's existing `setAthleteSession(athlete, email, sessionToken?)` needs an email string to persist locally, and this is the only place that value lives server-side.)
